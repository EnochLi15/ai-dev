# AI 晨报制作方案

> 版本：v1（2026-11-02 晚起草，基于当日一手信源验证）
> 配套文件：`research-methods.md`（业界调研笔记）、`brief-2026-11-03.md`（按本方案生产的首期晨报）

## 0. 一句话结论

用「分层信源 + 固定栏目 + 可溯源短摘要」的头部 newsletter 配方，做一个 **5 分钟读完、面向 AI Agent / AI Coding 开发者的中文晨报**：每晚从一手信源抓取 → 筛选 → 中文摘要 → 早晨推送，每条新闻都带原文链接和日期。

## 1. 目标读者与定位

- **读者**：关注 AI Agent 开发、AI Coding、前沿模型与产品动态的开发者/技术决策者（就是你）。
- **定位**：日报（每个工作日早晨 7:00），5 分钟读完，15-25 条高信噪比条目，全部可溯源。
- **不做什么**：不做搬运工式的全量罗列（机器之心等已覆盖），只保留「对开发者有行动价值」的条目。

## 2. 业界怎么做（调研要点，详细清单见 research-methods.md）

### 2.1 头部 AI 日报的共同配方

对标 TLDR AI、Ben's Bites、Latent Space、Import AI、机器之心等头部产品，共同点：

1. **固定栏目 + 固定格式**：每天同样的板块顺序、同样的条目格式（标题 + 一句摘要 + 链接），降低阅读成本。
2. **分层信源**：官方一手发布（博客/changelog）打底，社区热帖（HN/Reddit）验证热度，同行 newsletter 交叉补漏。
3. **人工/半人工筛选**：即使有 LLM 辅助，头条和「必读」由人拍板；条目贵精不贵多（每天 10-20 条）。
4. **短摘要 + 可溯源**：每条 1-2 句话 + 原文链接，读者 30 秒内决定是否深入。
5. **早晨定时投递**：抓取截止到前夜，早晨 6-8 点送达。

### 2.2 信息渠道地图（四层）

| 层 | 类型 | 代表 | 用法 |
|---|---|---|---|
| L0 | 一手信源 | OpenAI/Anthropic/Google/Meta 等官方博客与 changelog；Cursor/GitHub Copilot/Claude Code 更新日志 | 每晚定时抓取，最可靠 |
| L1 | 社区脉搏 | Hacker News（API）、Reddit、GitHub Trending、Hugging Face、arXiv | 验证热度、发现早期项目 |
| L2 | 人工精选 | TLDR AI、Latent Space、Ben's Bites 等英文 newsletter | 交叉补漏 + 学习选题 |
| L3 | 中文媒体 | 机器之心、量子位、新智元等 | 中文视角 + 国内动态 |

## 3. 我们的方案

### 3.1 信源体系（已验证可程序化抓取）

- **L0 一手（核心，已验证可达）**
  - Anthropic：`https://www.anthropic.com/news`（已抓通，含日期）
  - Cursor：`https://cursor.com/changelog`（已抓通）
  - GitHub（Copilot/平台）：`https://github.blog/changelog/`（已抓通，按月归档带日期）
  - arXiv：`https://arxiv.org/list/cs.AI/recent`、`cs.CL`（已抓通）
  - 机器之心 `https://www.jiqizhixin.com/`、量子位 `https://www.qbitai.com/`（已抓通）
  - Google（含 DeepMind）：`https://blog.google/technology/ai/rss/`（RSS）
  - 待补：OpenAI 官网（对脚本返回 403，用 Google News RSS `openai when:5d` 或新闻聚合替代）、Reddit（超时，用 HN 替代）、Hugging Face（超时，重试或用 arXiv 替代）
  - 社区：Hacker News Firebase API（`hacker-news.firebaseio.com/v0/topstories.json` + item 接口，已抓通）
- **L2/L3 订阅清单**：见 `research-methods.md`（英文 10+ 个、中文 8+ 个，标注频率与侧重）。

### 3.2 筛选标准（每条过六问）

1. **影响力**：影响多少开发者/用户？是版本发布、融资、政策还是传闻？
2. **相关性**：与 AI Agent 开发 / AI Coding / 前沿模型 / 产品的相关度。
3. **新颖度**：过去 24-72 小时内首次出现（过期不超过 7 天的重要进展可放「本周回顾」）。
4. **可验证**：有官方链接或 ≥2 个独立信源；无法溯源不收录。
5. **行动价值**：读者能因此升级版本、改架构、试新工具吗？
6. **中文读者视角**：对国内开发者的可用性（区域限制、价格、中文支持）。

### 3.3 栏目与格式（固定模板）

```
AI 晨报 · 2026-11-03（周二）
━━━━━━━━━━━━━━━━━
【今日头条】1-2 条，2-3 句摘要
【AI Agent 开发】3-5 条：框架、MCP 生态、agent 工程
【AI Coding】3-5 条：编码工具、编码模型、agentic coding
【前沿模型与研究】3-5 条：新模型、重要论文、基准
【产品与行业】3-4 条：产品更新、融资、政策
【GitHub 趋势榜】周榜为候选池（近 7 天新建 + 星标增速，GitHub search API），不是每天照抄榜单：
- **跨期去重（核心）**：台账 `trending-ledger.json` 记录每期已展示项目与当时星标，每天只报未出现过的 3-5 个 + 一句话快看；候选池不够时下探月榜/子方向检索补位
- **排序按增速**：stars / 库龄（而非星标总量），涨速突变优先；日榜（24-48h 新建）仅用于标记"今日新爆发"
- **子方向轮换**：Agent 框架 / Coding 工具 / 推理与模型 / 安全 / 多模态等轮换，保证每天面貌不同
- **周一特辑**：每周一出周榜全量盘点（Top 10 + 周度对比）
- **回访规则**：已报项目星标暴涨 ≥3 倍或发重大版本，才以一句话"回访"再提，否则永不重复
【必读】今日最值得精读的一篇 + 为什么
```

每条格式：`标题（日期，原文链接）— 1-2 句中文摘要，含关键数字/版本号`。

### 3.4 生产流程（当前半自动，后续可全自动）

```
每晚 22:00（T 日）
  1. 抓取：脚本拉取 L0 信源 + HN API（15 分钟）
  2. 初筛：按关键词+热度过滤，去重（跨源合并同一事件）
  3. 加工：LLM 生成中文摘要与分类草稿
  4. 复核：人工核对链接、日期、数字（防幻觉）
  5. 排版：套固定模板
早晨 07:00（T+1 日）推送
```

- 当前一期由 agent 完成 1-4 步（抓取结果全部存档于 `data/`，可复查）。
- 后续工程化：cron + 抓取脚本 + LLM 摘要 + 人工抽检；推送渠道可选微信公众号/飞书 webhook/邮件。

### 3.5 质量控制

- **零幻觉**：每条必须有当日实际抓取到的原文；摘要中的数字/版本号回原文核对。
- **可追溯**：`data/` 目录保存每晚原始抓取快照。
- **迭代**：每周复盘哪些条目后来被证明重要（召回率）、哪些是噪音（精确率），调整信源权重。
